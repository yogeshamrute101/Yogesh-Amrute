## AI Assistant Model
The system can orchestrate authorized AI providers for conversation, coding, research, documents, creative work, video, analysis and planning.

## Engineering Model
Existing project-aware engineering, diagnostics, RCA, CAPA, verification, audit and self-repair layers are intended to work together.

## Safety Model
High-risk actions require authorization, validation, audit and appropriate human review.
Harmful weapon construction and harmful-agent development are not enabled.

## Reality Boundary
Software capabilities do not automatically provide physical-world access. Hardware, APIs, credentials, sensors and authorized interfaces are required.

## Verification
A module existing on disk is not proof of runtime integration. Lint, build, tests and runtime verification remain required.
