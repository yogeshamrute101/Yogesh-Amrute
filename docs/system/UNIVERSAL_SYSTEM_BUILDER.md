# Universal System Builder

## Purpose

Create a reusable architecture for designing, building, integrating,
testing, deploying and maintaining large software systems.

## Supported system families

- ERP
- LIMS
- CRM
- HRMS
- SCM
- MES
- WMS
- QMS
- CMMS
- DMS
- EMR/EHR
- Finance systems
- Education systems
- E-commerce systems
- Media systems
- Custom enterprise systems

## Build lifecycle

DISCOVERY
→ REQUIREMENTS
→ ARCHITECTURE
→ DATA MODEL
→ UX
→ BACKEND
→ FRONTEND
→ INTEGRATION
→ SECURITY
→ TESTING
→ DEPLOYMENT
→ MONITORING
→ MAINTENANCE

## Engineering rules

1. Reuse existing capabilities before creating duplicates.
2. Requirements must have acceptance criteria.
3. Modules must declare dependencies.
4. Security and auditability are designed from the beginning.
5. Generated code is not considered production-ready until tested.
6. External services require authenticated integrations.
7. Regulated systems require applicable compliance review.
8. System templates are starting architectures, not copies of proprietary
   vendor implementations.

## Example

The builder can create an ERP or LIMS architecture, then generate its
requirements, modules, data model, APIs, UI structure, tests and deployment
plan.

It does not copy proprietary SAP, LIMS vendor source code, trademarks,
private algorithms, or confidential implementations.
