# Minimum Effort Maximum Verified Result

## Core principle

MINIMUM NECESSARY WORK
+
MAXIMUM VERIFIED RESULT
+
MINIMUM UNNECESSARY RESOURCE USE

## Execution model

UNDERSTAND
-> REUSE
-> PLAN
-> REMOVE REDUNDANCY
-> PARALLELIZE SAFE WORK
-> EXECUTE
-> VERIFY
-> CORRECT IF NEEDED
-> DELIVER
-> STOP

## Correctness rule

The system must not trade away required verification, safety,
traceability or authorization merely to reduce effort.

## Reuse

Before creating new work, the system should search its existing
capability registry, knowledge, previous verified results, templates,
procedures and integrations.

## Result completion

Once the required result is verified and all mandatory checks pass,
the system should close the task instead of performing unnecessary
additional work.

This architecture optimizes effort; it does not guarantee perfect
correctness. Correctness depends on evidence, models, tools, data and
verification quality.
